02 /

先匹配完整前缀，再检查状态是否可续算

这里的“前缀匹配”指推理服务的 prefix caching / APC / Radix Cache：新请求复用旧请求已经计算过的因果前缀，减少 prefill。它不等同于相似文本检索，也不等同于稀疏 indexer 的 Top-K 检索。

1. 输入身份一致从起点比较 token ID 序列；模板、特殊 token、图片等实际模型输入都属于上下文。
2. 缓存命名空间一致相同权重 / adapter、位置与 mask 语义、缓存表示；不同隔离 salt 不共享命中。
3. 找到可恢复的边界页、快照、窗口、压缩器状态，以及各层组件必须在同一位置支持续算。
4. 从边界继续计算恢复必要状态；复制可变状态或写时复制；重算尚未命中的尾部。
L = LCP(tokens_A, tokens_B)              // 最长公共 token 前缀
H = max { h ≤ L :
    身份与位置语义一致
    AND 所有层在 h 的续算依赖可用或可按实现重建
    AND h 满足引擎支持的命中 / 对齐规则
}
恢复 h 的状态 → 计算 tokens_B[h:]

分块哈希通常把父前缀哈希链接进去：hash(parent_hash, block_tokens, extra_keys)。所以即使某个块的文字相同，只要更早的上下文不同，它通常也是不同的缓存块。Radix 树则沿 token 路径表达同一类前缀身份。

“只需要尾部状态”不等于“只匹配尾部文本”。不同开头、相同最后 W 个 token，不能据此直接共享 SWA KV 或递推状态：深层 hidden state、投影得到的 K/V、状态与绝对位置仍可能不同。后文所有窗口或快照复用，都建立在完整公共前缀身份成立的前提上。
03 /

Linear / Mamba：匹配的是状态检查点

Linear attention

以简化形式为例，历史可累计为矩阵状态 Sₜ = Sₜ₋₁ + φ(kₜ)vₜᵀ，读出为 φ(qₜ)ᵀSₜ；归一化变体还需要累计向量。GDN、KDA 等采用门控、遗忘或 delta 更新，具体状态结构不同。

代表：Qwen3-Next / 3.5 / 3.6 的 Gated DeltaNet + full attention；Qwen3.8-Flash-Next 的 GDN + QSA；Kimi K3、Ling-3.1-flash 的 KDA + gated MLA。

Mamba / SSM

选择性状态空间模型通过输入相关的递推更新维护 SSM state。Mamba 系列通常还维护短卷积的历史缓冲区；只保存 SSM 矩阵并不足以恢复整个模块。

代表：Jamba2 的 Mamba + attention；Nemotron 3.5 Lightning 的 Mamba-2 + attention；Falcon-H1 系列的并行 Mamba-2 / GQA 分支。

命中规则：需要 h 处所有递推层的完整快照。命中该快照后，纯递推层不需要逐个恢复 1…h 的旧状态；但如果还混有 full / MLA / QSA 层，仍需同时满足这些层的缓存条件。

不能把最终状态任意“截短”。假设两请求共享前 1000 token，但只保留了 768 和 1024 处的快照：1024 的状态包含分叉后的输入，不能拿来续算 1000。应恢复 768，再计算 232 token 到公共前缀末端。门控递推一般不可逆，不能假设从 1024 回滚即可。

快照与内存的取舍：每个活动请求只需固定形状状态；若每隔 C token 存一个快照，前缀缓存中的快照总量仍会随检查点数量增长。稀疏保存快照能省缓存，但增加命中后重放的尾部。

架构依据见 [1]–[3]；实际快照命中逻辑见 [10]–[11]。Linear 与 Mamba 的状态不可跨模型或跨层类型互换。

04 /

SWA：前缀身份完整，物理 KV 可以只留窗口

Sliding Window Attention 限制每个 query 直接读取最近一段历史。它缩短直接访问范围，但深层表示可以间接携带更早的信息，因此不能把 W 理解成整个模型绝对的有效感受野。

如何保存

设本页 W 表示续算时需要的历史 token 数。在公共前缀长度 h 处，概念上需要 [max(0,h−W), h) 的逐层 KV 与正确的位置、环形缓冲区指针。

如果模型把“含当前 token 的注意力窗口”定义为 W，那么第一个续算 token 可能只需 W−1 个历史位置。真实引擎还会按页扩大保留量。

如何命中

只要该边界所需的连续尾部 KV 都在，窗口外早期物理 KV 可以已经被淘汰；但完整 token 前缀的索引身份仍必须存在或可验证。

若窗口中间缺页，不能把缺失位置当成被 mask 的 token。应选择其他有效边界，或按实现支持的方式重建。

命中规则：公共前缀成立 ∧ h 附近所需窗口连续可用 ∧ 位置 / 对齐一致。混有全局层时，还要保证全局层在同一 h 的所有历史 KV 可用。

例：两请求共享 4096 token，SWA 所需历史窗口为 512。局部层只保留末尾 512 个位置，也可能在 4096 命中；全局层仍要保留 0…4095 的缓存。若改从 3072 恢复，而旧窗口只覆盖 3584…4095，则这个较早边界并不自动有效。

代表：Gemma 4、MiMo-V2.6、Step-5-Preview、Command A+ 等采用 local / global 混合。每层窗口可能不同，不能把所有 SWA 层固定成同一个 W。

SWA 的可用性不随前缀长度单调变化。混合缓存不能简单对各组件“独立最长命中长度”取最小值后直接使用；必须在这个候选位置重新检查每个组件。原来较长位置的可用窗口，不一定支持退到较短位置。

vLLM 的 SlidingWindowManager 从右向左找满足连续窗口块的边界；SGLang 的 SWA 组件也检查窗口可用范围。见 [10]–[11]。

05 /

压缩 × 稀疏：存多少，与读多少

压缩把多份历史表示汇聚成更少的表示；稀疏让每个 query 只计算选定位置的注意力。压缩 indexer 的键，不一定等于压缩主 attention 的 KV；Top-K 很小，也不代表可以删除其他候选历史。

DeepSeek-V4 · 压缩主历史

CSA：压缩后选读；HCA：更高压缩率

CSA = Compressed Sparse Attention；HCA = Heavily Compressed Attention。DeepSeek-V4 的实现包含 r=4 与 r=128 的路径，并配合 SWA 局部历史。CSA 对较细的压缩表示再做稀疏检索；HCA 使用更高倍率压缩的历史表示。

需要保留什么？

已完成的压缩历史、原粒度局部窗口、压缩器的 KV / score 等构造状态；有索引器时还需要其键或压缩状态。r=4 路径存在重叠压缩，因此即使 h 恰好是 r 的倍数，也不能一概认为压缩器已无历史依赖。

前缀匹配规则

先匹配原始 token 前缀，再恢复 h 对应的压缩历史和构造状态。若边界残留或重叠状态未保存，需要从可重建的较早边界重放；仅有 floor(h/r) 个压缩条目，通常不足以证明能继续构造下一条。

“压缩粒度对齐”只是可能的约束之一。实际还要看缓存页、重叠范围、索引器与 SWA。不能将 h % r == 0 当作所有压缩架构的充分条件。

见 [4]、[12]。DeepSeek-V4.1 已改为 CSA2：跨层主 KV / indexer K / Top-K 索引共享与分层检索，不能直接沿用 V4 的 CSA/HCA 分类。其官方说明还有 SWA Bounded Replay；这属于特定模型的重建机制，不是任意 SWA 都能只重算窗口输入。

DeepSeek Sparse Attention · token 选择

DSA：用轻量 indexer 选择历史 token

DeepSeek-V3.2 系列引入 DSA。轻量索引器给候选历史打分、选出 Top-K token，主 attention 在被选位置上读取 MLA 缓存。MLA 是特征维度上的 KV 表示压缩，不能据此认为历史 token 数量已被压成常数。

需要保留什么？

后续 query 可能读取的历史 MLA 表示，以及索引器需要的历史键 / 等价信息。默认不能删除上一个 query 没选中的历史，因为下一个 query 的 Top-K 可以完全改变。

前缀匹配规则

公共 token 前缀与主历史缓存、indexer 历史共同命中。新 query 应执行新的选择；无需把它的 Top-K 集合与旧 query 比较。只恢复上一轮选中的 K 个位置，无法普遍保证精确续算。

主要减少主注意力的历史读取和计算。主缓存及索引缓存仍可能随 N 增长；轻量索引本身也可能扫描随 N 增长的候选，不能把整个算子的复杂度直接写成 O(K)。

代表：DeepSeek-V3.2 / V3.2-Exp；混合例子有 dots3 的 DSA + SWA。见 [5]。

MiniMax Sparse Attention · block 选择

MSA：按块选择，执行稀疏 attention

此处 MSA 特指 MiniMax Sparse Attention。MiniMax-M3 将 dense GQA 层与 MSA 层混合；官方 MSA 仓库提供 block-sparse / Top-K 选择与稀疏 attention 内核。局部块、全局候选和选择策略需按具体模型配置理解。

需要保留什么？

供后续检索的主历史 K/V 或其模型规定的表示，以及选择器所需的索引 / 块信息。若实现使用摘要，需要可恢复其构造状态；块表、量化 scales 和位置映射也要一致。

前缀匹配规则

缓存身份仍由原始公共前缀决定，不由“选中了哪些块”决定。检查主 KV、选择元数据和边界块能否在 h 继续维护。attention 稀疏块大小与缓存分配页大小是不同概念，不应直接等同。

官方算子的速度或内存占用收益，不等于整个模型历史缓存 O(1)。MiniMax Text-01 / M1 的 Lightning Attention 不能套用到 M3 的 MSA 描述中。

MiniMax-M3：前 3 层 dense，后 57 层 sparse（本地配置快照）。模型介绍与算子仓库见 [6]。

Qwen Sparse Attention · micro-block 选择

QSA：压缩索引键，按微块读取主 KV

Qwen3.8-Flash-Next 用 QSA 替换原先的 gated attention 分支，与 Gated DeltaNet 混合。官方说明强调 micro-block 粒度；所核对参考实现将 indexer 的历史键分组池化，对块打分，再展开为对应 token 的主 attention mask。

需要保留什么？

主 attention 历史 KV、indexer 历史键或等价块表示、未成块尾部；还需同一边界的 GDN 状态。该参考实现直接保留原始 indexer keys，再构造池化块，并不只存压缩摘要。

前缀匹配规则

在 h 同时恢复 QSA 历史与 GDN 快照。参考实现在可见完整块之外还纳入未成块尾部；不能只保留完整块，直接丢弃尾部 token。新 query 重新检索微块，历史 Top-K 集合不是公共前缀身份。

QSA 的“压缩”首先发生在索引侧；主 KV 仍可保留逐 token 历史。它与 CSA 压缩主历史表示的路径不同，不能因都有 block pooling 就认为缓存规则相同。

模型卡见 [7]；本地保存的 Transformers 参考实现见 [8]。参考 eager 实现用于解释语义，不代表生产内核的运行成本。

命中全部 prompt，是否就完全不算了？

KV / 递推状态通常不包含生成首个新 token 所需的最终 logits。服务可能保留末 token 重算，也可能单独缓存 logits / hidden state。因而最终跳过的 token 数还会受 prompt_len−1、对齐和实现策略影响。交互示例只计算可恢复状态的边界，不模拟 logits 路径。

缓存命中会改变注意力计算结果吗？

在输入、位置、mask 与状态表示一致的前提下，精确前缀复用应保持模型语义。量化、不同 kernel 的浮点误差和非确定性可能使结果不逐位一致；近似重建或改变缓存精度不能自动视作逐位等价。

能从缺失的局部 KV，只重算最后 W 个 token 恢复吗？

一般不能直接这样推断：计算深层窗口内的 KV 可能仍依赖更早的输入与其他层状态。必须有架构或实现专门保证的恢复路径。DeepSeek-V4.1 的官方 SWA Bounded Replay 是特定机制，不能外推到所有多层 SWA 模型。

MLA、GQA、KV 量化在分类中处于什么位置？

GQA / MQA 共享 KV heads，MLA 在特征维度采用潜变量表示，量化减少每个元素的字节数；它们可以与窗口、序列压缩和稀疏选择组合。它们本身都不意味着历史 token 数量变为 O(1)，也不会把完整前缀匹配变成任意后缀匹配。
